# Grafana status display on the K3 (issue #4)

A K3 left on its charger shows a small homelab status dashboard on its e-ink screen and redraws it
every few minutes. The K3's browser is far too old for Grafana, so the work is split:

```
monitor-01                                              Kindle (dfair_lab, VLAN 20)
Grafana ── image renderer ── koreader-d00901-dashboard  KUAL > K3 status dashboard
             (every 2 min) → /srv/k3-dashboard/k3.png  ← wget every 5 min → fbink draws it
                             served on :8090 (HTTP)
```

- **Server:** `koreader-d00901-dashboard render` asks Grafana's image renderer for the `k3-status`
  dashboard at 1200x1600, halves it to 600x800 and reduces it to the K3's 16 grey levels. (It renders
  at twice the size because Grafana switches to its one-column phone layout on narrow screens.)
- **Kindle:** the installer copies a KUAL extension, `extensions/k3dash/`. It turns Wi-Fi on, stops
  the screensaver, fetches `k3.png` over plain HTTP and draws it with KOReader's `fbink`.
- **Why plain HTTP:** the K3 cannot verify Caddy's internal CA, and its TLS is too old for modern
  servers anyway. The image is a status picture with no credentials in it, and the router only lets
  the Kindles' addresses reach that one port.

## What the dashboard shows

`k3-status` is a separate, small dashboard, so the Infrastructure Overview dashboard stays as it is.
Its queries are copied from that dashboard (home_lab_docs `docs/services/dashboards/infra-overview.json`):

| Panel | Query |
| ----- | ----- |
| Targets | `up` for every scrape job, plus Caddy's upstream health for Grafana and Kuma. Anything down shows as black **DOWN**. |
| Proxmox host, monitor-01 | CPU, RAM and root disk in percent, black above 85% |
| llm-01 GPU | Load, VRAM in percent, temperature |
| CI runners | Running jobs (`gha_runner_current_job == 1`), or "all runners idle" |
| (footer) | The time the image was rendered, so a stale screen is obvious |

The layout is generated by `scripts/make_k3_dashboard.py` (run `make dashboard-json` after editing it).

## Server setup on monitor-01

### 1. Image renderer

Add the renderer next to Grafana in `/opt/monitoring/compose.yml`, and point Grafana at it:

```yaml
services:
  renderer:
    image: grafana/grafana-image-renderer:v5.12.10
    restart: unless-stopped
    environment:
      AUTH_TOKEN: "<random string, same as below>"
      GOMEMLIMIT: 768MiB
    mem_limit: 1g

  grafana:
    # ...existing settings...
    environment:
      GF_RENDERING_SERVER_URL: http://renderer:8081/render
      GF_RENDERING_CALLBACK_URL: http://grafana:3000/
      GF_RENDERING_RENDERER_TOKEN: "<the same random string>"
```

Grafana's guide asks for 16 GiB and 4 cores for the renderer, but that's sized for many concurrent
renders. One small dashboard every two minutes needs far less, so this caps it at 1 GiB. If renders
fail with out-of-memory errors in `docker logs renderer`, raise `mem_limit` (and `GOMEMLIMIT` with it).
The renderer port is only on the compose network, not published.

### 2. The dashboard and a token

1. Import the dashboard: `koreader-d00901-dashboard grafana-json > k3-status.json`, then in Grafana use
   Dashboards > New > Import, upload the file and choose the Prometheus data source.
2. Create a service account with the **Viewer** role (Administration > Users and access > Service
   accounts) and add a token to it.

### 3. Render and serve

```sh
sudo useradd --system --home-dir /nonexistent --shell /usr/sbin/nologin k3dash
sudo install -d -o k3dash -g k3dash /srv/k3-dashboard
sudo install -d -m 0750 -g k3dash /etc/k3-dashboard
sudo sh -c 'umask 027; cat > /etc/k3-dashboard/token'   # paste the token, Enter, then Ctrl-D
sudo chgrp k3dash /etc/k3-dashboard/token

# Python 3.14 in its own folder, readable by k3dash (Debian 13 ships 3.13). Needs uv installed.
sudo env UV_PYTHON_INSTALL_DIR=/opt/k3-dashboard/python uv venv --python 3.14 /opt/k3-dashboard/venv
sudo uv pip install --python /opt/k3-dashboard/venv/bin/python 'koreader_D00901[dashboard]==0.4.0'

sudo cp deploy/k3-dashboard/k3-dashboard-*.service deploy/k3-dashboard/k3-dashboard-render.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start k3-dashboard-render.service && ls -l /srv/k3-dashboard/k3.png
sudo systemctl enable --now k3-dashboard-render.timer k3-dashboard-http.service
curl -fsS -o /tmp/k3.png http://192.168.10.158:8090/k3.png && file /tmp/k3.png   # PNG, 600 x 800, 8-bit grayscale
```

The units are in [`deploy/k3-dashboard/`](../deploy/k3-dashboard/). The render unit runs with a
read-only system except `/srv/k3-dashboard`. A failed render leaves the previous image in place,
because the file is replaced in one step. Check it with `journalctl -u k3-dashboard-render`.

### 4. Router rule (Flint 2)

Trusted (VLAN 20) cannot reach Lab (VLAN 10) by default. Give each Kindle a DHCP reservation on
`dfair_lab`, then allow just those addresses to port 8090 on monitor-01:

```sh
uci set firewall.k3_dashboard=rule
uci set firewall.k3_dashboard.name='Allow-K3-dashboard'
uci set firewall.k3_dashboard.src='trusted'
uci set firewall.k3_dashboard.dest='lab'
uci add_list firewall.k3_dashboard.src_ip='192.168.20.<kindle 1>'   # one line per Kindle
uci set firewall.k3_dashboard.dest_ip='192.168.10.158'
uci set firewall.k3_dashboard.dest_port='8090'
uci set firewall.k3_dashboard.proto='tcp'
uci set firewall.k3_dashboard.target='ACCEPT'
uci commit firewall && service firewall reload
```

Record the rule in home_lab_docs' firewall page like the other targeted rules.

## Kindle setup

1. The K3 has 2.4 GHz 802.11b/g with WPA2-PSK only. `dfair_lab` must offer WPA2 on its 2.4 GHz radio
   (WPA2/WPA3 mixed is fine, WPA3-only is not). Join it from the Kindle's own Settings > Wi-Fi.
2. Install the extension over USB, with the CLI or the TUI's **Status display** fields:

   ```
   koreader-d00901 --only dashboard --dashboard-url http://192.168.10.158:8090/k3.png
   ```

   `--dashboard-interval SEC` sets the refresh (default 300, minimum 60).
3. Eject, then on the Kindle open **KUAL > K3 status dashboard > Start**. The first image appears
   within a few seconds. **Show it once now** draws once. **Stop** ends the loop, lets the screensaver
   run again and repaints the home screen.

While it runs, pressing a key brings back the normal Kindle screen until the next refresh redraws
the dashboard. A failed fetch writes a one-line notice at the bottom of the screen and is logged
to `extensions/k3dash/k3dash.log` on the Kindle. The loop does not survive a reboot, so press
Start again after one.
